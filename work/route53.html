AWS Route 53, rebuilt

A working clone of Route 53's core: create hosted zones, add and edit DNS records across nine record types, and search them, with a dashboard modelled on the AWS console. The front end and API are deployed separately.

The API runs on Render's free tier, so the first request after a quiet spell can take up to 30 seconds while the server wakes.

01 · Architecture

Two deployments, one contract

I kept the front end and back end fully decoupled so each could be built, deployed and replaced on its own. The only thing they share is the REST contract under /api/v1, and CORS is locked to localhost and the production Vercel origin.

02 · Data model

Zones own their records

Two tables in a one-to-many relationship. The ORM relationship uses cascade="all, delete-orphan", so deleting a hosted zone removes its records with it instead of leaving orphans behind.

03 · API

Nine endpoints, typed both ways

Each resource has separate Pydantic models for what comes in (HostedZoneCreate) and what goes out (HostedZoneResponse), so the API never echoes fields a client shouldn't set, like id or created_at. Missing zones and records return a 404 instead of failing silently. FastAPI generates the Swagger docs from the same models.

04 · Front end

Built to feel like the console

  • Zone detail page with create, edit and delete for records in one form that switches between modes.
  • Instant search across record names and values, filtered on the client, with pagination that resets when the query changes.
  • Session persistence through a token in localStorage, with dashboard routes closed to signed-out users.
  • The rest of the console (traffic policies, health checks, resolver, profiles) exists as placeholder pages, so navigation behaves like the real product.
05 · Next

What I'd do next

Real authentication

Replace the mock login with hashed passwords and signed JWTs checked on every API route, not only in the front end.

Validate records by type

Constrain record_type to an enum and check values per type: IPv4 for A, IPv6 for AAAA, a hostname for CNAME, a priority for MX.

Move to Postgres

Render's free tier doesn't keep files between deploys, so SQLite data can reset. A managed Postgres would keep it, with migrations through Alembic.

Tests and server-side search

Add pytest coverage for the CRUD layer, and move search and pagination to the API for zones with thousands of records.
